# 改善アイデア・メモ (開発中に気づいたもの)

実装済みの機能から漏れた改善候補を、忘れないうちに書き留めておく。

## 他ライブラリ調査 (2026-08) で得た候補

- **非連続ピン対応 (Pimoroniの手法)**: pimoroni-picoのencoder.pioは
  `jmp pin`(EXECCTRL_JMP_PINで任意GPIO指定可)と`in pins, 1`(in_baseも任意)を
  組み合わせ、任意の2ピンでquadratureを読んでいる。substepプログラムは
  「IN PINS,2 + 16エントリのジャンプテーブル + 定13サイクルループ」前提で
  32命令フルなので、取り込むには全面書き直しが必要。ループサイクル数が増えて
  最大ステップレートが下がるトレードオフ込みで、需要が出たら着手。
- **PIO内デバウンス (Pimoroni)**: 状態変化後に~500サイクルの固定待ちを入れている。
  RP2040はGPIOのSchmittトリガが標準有効で、quadratureは片相バウンスに正味誤差が
  出ない(往復カウントで相殺)ため、当面不要と判断。
- **DMA読み出し (adamgreen/QuadratureDecoder方式)**: FIFOをDMAでリングバッファに
  流せばCPUのFIFOドレインすら消える。現状の読み出しは数µsなので優先度低。
  タイムスタンプとの対応付けの設計が課題。

## 調査して見送ったもの (理由付き)

- **PLL型の速度・位置推定 (ODrive/VESC)**: 遷移タイミング直接計測+ステップ境界
  クランプの現方式が低速で優位。平滑が欲しければユーザー側LPFで足りる。
- **x1/x2カウントモード (STM32 TIMエンコーダモードの機能)**: 位相不均等の影響を
  減らす目的ならサブステップ+位相較正で解決済み。分解能を落とす意味はない。
- **STM32 TIM入力キャプチャの
  デジタルフィルタ相当**: PIO命令空間が無い。SchmittトリガとRCフィルタで代替
  (READMEに記載)。
- **ODriveのuse_index + index_offset保存**: zeroOnNextIndex(値指定可) +
  getPhases/setPhasesの永続化で同等のことができる。lastIndexSpacing()で
  脱調検出も追加済み。

## 精度・推定

- **1回転周期の誤差補正**: 磁気エンコーダ(AS5600/AS5047のABIモード等)の主要誤差は
  磁石の偏心による「1回転に1周期」の系統誤差で、現在の位相較正(4ステップ周期)では
  補正できない。Z相があれば1回転の基準が取れるので、回転内位置に対する補正テーブル
  (低次高調波数個で十分)を学習する機能が作れる。
- **インデックスラッチのステップ境界スナップ**: 実エンコーダのZパルスは特定の
  quadrature状態にゲートされていることが多い。ラッチ位置を最寄りのステップ境界に
  スナップするオプションを付ければ、ISR遅延由来の誤差(数substep)をゼロにできる。
- **超低速時のidle timeout自動化**: 現在は固定値。直近の遷移間隔から適応的に
  伸ばすことも考えられる(ただし複雑さに見合うか要検討)。

## API・堅牢性

- **クロスコア安全なスナップショット**: 現在は「1インスタンス1コア」前提。
  seqlockかspinlockで両コアから読めるようにする。
- **end() / PIOリソースの解放**: 現在はclaimしたPIOブロックを返さない。
  全インスタンスがend()したらブロックを解放する管理を入れる。
- **attachIndexのコア制約解消**: raw IRQハンドラ登録が呼び出しコア依存。
  コアごとのディスパッチャ登録フラグにすれば制約を外せる。
- **単位変換ヘルパ層**: substeps→rad/rev/rpmの変換をPPR設定付きの薄いラッパで
  提供するか検討(コアは整数のまま維持)。

## ビルド・CI

- **pico-sdk CIビルド**: pico_sdk_example/はCIでビルドしていない。
  pico-sdkのdockerイメージかsetup actionでビルドジョブを追加する。
- **pioasm再生成スクリプト**: substep_encoder.pio.h は本家の生成物を改名した
  チェックイン済みヘッダ。pioasmで再生成する手順/スクリプトを用意する。

## エコシステム

- **Nidec_24H_BLDC_Pico の移行**: PicoEncoder依存をSubstepEncoderに切り替える。
  update()間引き機構(setEncoderUpdateInterval)はまるごと不要になる。
  float精度問題(160回転超でgetRadが粗くなる)もint64位置で根治。
- **本家へのPR**: 時間基準の停止判定は汎用的な修正なのでPicoEncoderにも
  提案する価値がある(idle_stop_samplesをidle_stop_us に)。
- **較正値の永続化例**: getPhases()の結果をEEPROM/フラッシュに保存・復元する
  exampleを追加する。
